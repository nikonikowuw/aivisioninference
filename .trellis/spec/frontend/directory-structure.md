# Frontend Directory Structure

## Package Roles

- `web/src/views/admin/`: route-level admin pages. Domain modules live here, such as devices, media, smart records, AI tasks, algorithm packages, edge nodes, GB28181, persons, and system config.
- `web/src/components/`: reusable components. Use this for cross-page building blocks such as video players, search bars, pagination, empty states, dialogs, cards, charts, sidebar/navbar, and field wrappers.
- `web/src/services/`: API boundary. All HTTP calls go through `services/api.ts` or typed feature wrappers such as `services/edgeNode.ts`.
- `web/src/hooks/`: reusable stateful browser logic such as pagination, filtering, WebSocket, date formatting, and throttled inference overlays.
- `web/src/router/`: generated/dynamic route handling and static route config.
- `web/src/theme/`: Chakra theme tokens, components, foundations, and color-mode behavior.
- `web/src/locales/`: i18next resources by locale and namespace.
- `web/src/types/`: shared TypeScript types that are not owned by one service file.
- `web/src/utils/`: pure helpers with no component lifecycle ownership.

## Routing Pattern

Admin routes are menu-driven. `web/src/router/index.tsx` maps backend `Menu.code` values to dynamic imports and generates sidebar routes with `menu:<code>` i18n keys. Add a new admin page by updating the menu mapping and locale resources; keep the menu code stable because backend menus and frontend translations depend on it.

The router wraps lazy pages in `Suspense` and `ErrorBoundary`. Preserve the cache/HMR logic in `lazyCache` when changing dynamic route generation.

Reference files:
- `web/src/router/index.tsx`
- `web/src/router/index.test.tsx`
- `web/src/router/types.ts`

## Service Pattern

Feature service files define request/response types next to the API calls. `web/src/services/edgeNode.ts` is a good local pattern: it defines `EdgeNode`, heartbeat/deployment types, a small `buildQuery` helper, and an exported `edgeNodeApi` object.

Do not call `fetch` from components. Use `request<T>()` from `web/src/services/api.ts` so auth headers, `Accept-Language`, error translation, response parsing, and unauthorized redirects stay consistent.

## Generated Files

`web/src/router/index.tsx` carries a generated header. Treat it carefully: if route generation is regenerated by project tooling, move durable custom logic into config/helpers where possible.

## Common Mistakes

- Adding display text in a page without locale entries.
- Creating a new per-page fetch wrapper instead of using `request<T>()`.
- Placing a single-use route page in `components/` instead of `views/admin/`.
- Importing heavy media/chart libraries into shared top-level code rather than route/component lazy paths.
