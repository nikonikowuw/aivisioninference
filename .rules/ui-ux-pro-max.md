# 前端 UI/UX 与可访问性规范

本规范适用于 `web/` 下所有 React 页面、布局和组件。原则是：沿用 Chakra UI 能力，保证后台管理场景的可读性、可访问性、响应式和稳定反馈。

## 1. 可访问性

- 常规文本与背景对比度必须 `>= 4.5:1`，大文本、图标、关键边界对比度必须 `>= 3:1`。
- 禁止全局隐藏键盘焦点样式；所有交互元素必须具备可见 `focus-visible` 状态。
- 纯图标按钮必须提供 `aria-label`，或包含仅屏幕阅读器可见文本。
- 表单控件必须有可感知 label；不能用 placeholder 作为唯一标签。
- 错误提示应通过 `FormControl`、`FormErrorMessage`、`aria-describedby` 与字段关联。
- 视觉顺序应与 DOM 顺序一致，禁止用绝对定位或反向 flex 破坏键盘导航路径。

## 2. Chakra 表单与反馈

- 表单优先使用 Chakra 的 `FormControl`、`FormLabel`、`Input`、`Select`、`Textarea`、`FormErrorMessage`。
- 提交失败时应定位到第一个错误字段，长表单应滚动到错误位置。
- Toast、Alert、Modal、Confirm 文案必须走 i18n，并区分 success、warning、error、info。
- 删除、停用、下发任务、停止流等破坏性操作必须二次确认。
- 上传、导入、模型/算法包校验等长任务必须展示进度或后台任务状态。

## 3. 触控与响应式

- 独立触控目标最小热区为 `44 × 44px`，相邻触控元素净间距不小于 `8px`。
- 核心操作不能只依赖 hover；移动端必须提供点击、长按或始终可见的替代交互。
- 布局优先使用 Chakra responsive props 和项目 breakpoints，避免写死桌面尺寸。
- 移动端禁止意外横向滚动；需要横向滚动的表格必须包裹在明确滚动容器内。
- 固定 Header、底部操作栏、播放器控制条必须预留安全区和内容遮挡空间。

## 4. 颜色、暗色模式与图标

- 新增业务 UI 优先使用 Chakra semantic tokens 和 `useColorModeValue`。
- 允许历史样式保留 Hex/RGBA；新增重复色值应沉淀到 theme 或共享常量。
- 暗色模式禁止简单反色；需要单独校验文字、图标、边框、图表网格线和 tooltip。
- 图标优先沿用现有 `react-icons` 与 `@chakra-ui/icons`，不要为少量图标新增第三方图标库。
- 同一功能区的图标风格、尺寸和描边应保持一致。
- 禁止用 Emoji 作为具备操作含义的功能图标。

## 5. 性能与稳定性

- 图片优先使用 WebP/AVIF；大图、封面、截图应提供明确尺寸或 `aspect-ratio`，避免 CLS。
- 单列表或网格一次渲染超过 50 项时，应使用分页、服务端筛选或虚拟滚动。
- 表格默认不要一次性拉取全量数据；优先使用后端分页、排序和筛选。
- 视频、图表、富文本、地图等重型组件必须避免阻塞首屏，优先放到懒加载路由或按需加载组件中。
- WebSocket、轮询、播放器实例、定时器必须在组件卸载时清理。
- 错误边界或局部 fallback 应覆盖媒体播放、图表渲染、动态路由组件加载失败等场景。

## 6. 动画与动效

- 动画只使用 `transform` 和 `opacity` 等低成本属性，禁止对 `width`、`height`、`top`、`left`、`margin` 做连续动画。
- 微交互控制在 150–250ms，复杂展开/抽屉/弹窗控制在 200–400ms。
- 必须支持 `prefers-reduced-motion`，低动效模式下关闭非必要动画。
- Loading skeleton、spinner、进度条应与实际等待时间匹配，避免闪烁或误导。

## 7. Admin 场景细则

- 表格必须包含空状态、加载态、错误态和分页态。
- 批量操作必须清楚展示已选择数量、作用范围和取消入口。
- 状态字段应使用统一 Badge 或 Tag 表达，颜色含义在全系统保持一致。
- 权限控制相关按钮应根据后端菜单/权限状态隐藏或禁用，禁用态需说明原因。
- 媒体监控页面必须展示连接中、播放中、断流、重连、无权限、设备离线等状态。
