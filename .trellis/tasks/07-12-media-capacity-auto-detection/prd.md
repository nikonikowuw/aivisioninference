# 实现媒体容量自动探测适配器

## Goal

在静态媒体容量调度闭环完成后，为各 Engine HAL 增加可验证的解码、编码和网络容量自动探测，为新节点生成安全的容量建议值，同时保留运维显式配置的最终控制权。

## Background

- 父任务 `07-12-edge-node-media-scheduler` 的 MVP 以静态容量为权威，避免在缺少设备证据时硬编码平台理论能力。
- 当前 HAL capability 只描述功能支持，不包含并发容量。
- 不同 SoC、板卡、BSP、驱动、CANN 和散热条件会改变实际媒体并发能力，不能只按平台名称推断。
- 本任务是父任务的强制连续工作，父任务不得在本任务完成前归档。

## Requirements

### Detection contract

- 在 HAL/monitor 边界定义统一的媒体容量探测结果，包括来源、置信度、采集时间、解码建议槽、编码建议槽和带宽建议上限。
- 区分硬件 API 报告值、设备基线实测值和保守回退值，不把估算值标记为精确硬件上限。
- 自动探测结果只提供默认值或建议值，不覆盖已存在的运维显式配置。

### Platform adapters

- 对仓库当前支持的 RKMPP 和 VideoToolbox HAL 实现适配器。
- 新增 Ascend/DVPP 或其他 HAL 时通过相同接口接入，不在调度器内写平台分支。
- Rockchip 和 Ascend 的实现必须先建立对应物理设备的序列号、BSP/驱动/CANN 版本与实测基线，禁止跨设备复用未经验证的容量数据。

### Verification

- 提供受控媒体压力测试，分别测量解码、编码和混合流稳定并发能力。
- 测试必须定义分辨率、编码格式、帧率、码率、持续时间、温度和允许的丢帧/错误阈值。
- 探测建议值必须使用安全裕量，不能直接采用首次失败前的最大并发值。
- 探测失败、权限不足或平台不支持时回退到父任务的静态配置模式。

## Acceptance Criteria

- [ ] 统一探测接口不依赖具体 RKMPP、DVPP 或 VideoToolbox 类型。
- [ ] RKMPP 和 VideoToolbox 能生成带来源与置信度的容量建议。
- [ ] 运维显式容量配置始终优先于自动探测结果。
- [ ] 未验证设备不会使用其他板卡缓存的容量基线。
- [ ] 探测失败不会阻止 Engine 启动，节点按静态配置或不可调度策略安全降级。
- [ ] 压力测试覆盖解码、编码和混合流，并记录可复现的测试条件。
- [ ] 父媒体调度器能够消费探测建议，并通过多节点集成验收。

## Dependencies

- 必须在 `07-12-edge-node-media-scheduler` 的静态容量与动态使用量 MVP 完成后立即继续。
- 依赖父任务已定义的容量字段、指标协议和调度准入接口。

## Notes

- 这是复杂且需要真实设备证据的任务，实现前必须补充 `design.md`、`implement.md` 和设备基线采集计划。
- 若平台数量导致单任务无法独立验收，应在本任务下继续按平台创建子任务，但不得把自动探测降级为可选后续事项。
