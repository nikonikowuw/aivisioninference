# 前端视觉设计规范

本规范适用于 `web/` 下 React + Vite + Chakra UI 后台管理前端。自研 React Admin UI：入口为 `web/src/index.tsx`，根组件为 `web/src/App.tsx`，Admin 动态路由由后端菜单驱动。

## 1. 设计目标

- 后台管理系统以清晰、一致、可维护为第一优先级，避免为了风格化牺牲数据密度、可读性和操作效率。
- 品牌页、登录页、Dashboard 大屏、媒体监控页可以使用更强视觉表达；表格、表单、系统配置页保持克制统一。
- 新增 UI 必须复用 Chakra theme、项目组件和既有布局模式，禁止引入第二套设计系统。
- 视觉改造必须同时考虑亮色/暗色模式、响应式布局和 i18n 文本长度变化。

## 2. Chakra Theme 与 Design Tokens

- 主题入口在 `web/src/theme/`，新增全局颜色、字体、断点、组件 variant 时优先修改 theme，而不是在页面内散落样式常量。
- 业务组件优先使用 Chakra props 与 semantic token，例如 `bg`、`color`、`borderColor`、`useColorModeValue`。
- 新增页面不得创建 `design-tokens.json` 等独立 token 源；本项目 token 源以 Chakra theme 为准。
- 允许在图表、视频叠层、canvas、第三方播放器适配中局部使用 Hex/RGBA 常量，但应集中定义并附带用途命名。
- 禁止在多个页面复制同一组颜色、阴影、渐变；应抽成 theme token、组件 variant 或共享样式函数。

## 3. 字体与排版

- 当前项目全局字体以 `DM Sans` 和 Chakra theme 配置为基础；不要在普通业务模块随意切换字体家族。
- 标题、统计数字、表格、表单标签必须形成清晰层级，避免所有文字同字号同字重。
- 中文、英文、日文、韩文、印尼语、繁体中文都必须留足空间；按钮和表头不能依赖固定短文案。
- 数字、时间、状态、金额等数据展示应统一格式化，避免同一页面混用多种日期/数字格式。

## 4. 布局与信息密度

- Admin 页面优先遵循现有 Sidebar、Navbar、Card、Table、Form、Modal 布局节奏。
- 表格页必须提供明确的筛选区、操作区、分页区和空状态；复杂筛选应可折叠。
- Dashboard 和监控页可以使用非对称布局，但不能破坏响应式断点和键盘导航顺序。
- 避免等宽卡片机械堆叠；统计卡片应通过尺寸、图标、趋势、颜色或分组表达优先级。
- 移动端优先保证核心操作可达，复杂表格可降级为卡片列表、横向滚动容器或重点字段摘要。

## 5. 图表与视频场景

- 项目同时使用 ECharts、ApexCharts、HLS、FLV；新增图表或播放器前先复用现有组件。
- 图表文案、legend、tooltip、空状态必须走 i18n，不硬编码展示文本。
- 图表颜色应来自 theme 或集中配置；暗色模式下必须校验网格线、tooltip、legend 对比度。
- 大型图表、播放器、回放组件属于重型依赖，应配合路由级懒加载或组件级动态加载。
- 视频监控页必须优先保证低延迟、错误恢复、加载状态、断流提示和重连反馈。

## 6. 动效与反馈

- 普通 hover、focus、展开/收起优先使用 CSS 或 Chakra 过渡能力。
- 复杂拖拽、入场、手势或路由切换可使用现有 `framer-motion`，不要新增动画库。
- 动效时长保持克制：微交互 150–250ms，抽屉/模态框 200–400ms。
- 必须支持 `prefers-reduced-motion`，不得让动画成为理解信息的唯一方式。
- 提交、删除、上传、任务启动、流媒体连接等异步操作必须提供 loading、success、error 状态。

## 7. i18n 零硬编码

- UI 展示文本必须使用 `react-i18next`，包括按钮、表头、placeholder、toast、modal、tooltip、图表 legend、空状态和错误提示。
- locale 资源位于 `web/src/locales/`，新增业务模块应按模块拆分翻译文件。
- 支持语言以 `web/src/i18n/config.ts` 为准，当前包括 `zh-CN`、`zh-TW`、`en-US`、`id-ID`、`ja-JP`、`ko-KR`。
- 菜单文本遵循现有 `menu:<code>` 规则，后端菜单 code 与前端翻译 key 必须保持一致。
- API 错误展示不得直接使用后端原始错误字符串，应走 `services/api.ts` 的翻译映射机制。

## 8. 自检清单

- 新页面是否复用了 `web/src/theme/`、现有布局和通用组件。
- 亮色/暗色模式下文字、边框、图表、状态色是否可读。
- 所有展示文本是否已加入 locale 资源。
- 表格、表单、弹窗、空状态、错误态、加载态是否齐全。
- 重型图表/视频依赖是否懒加载或仅在目标路由加载。
- 移动端是否无意外横向滚动，核心操作是否可触达。
